# 注释检查

对代码进行全面注释质量审查。支持 Python（后端）和 TypeScript/React（前端）。

## 参数

- 无参数 → 检查 `backend/app/` 和 `frontend/src/` 下所有代码文件
- `backend` / `后端` → 只检查 Python 后端
- `frontend` / `前端` → 只检查 TypeScript 前端
- `<文件或目录路径>` → 只检查指定目标
- `quick` / `快速` → 只检查注释覆盖率（不逐行验证匹配度）

## 检查维度

### 一、注释覆盖率（3:7 比例）

目标：每 10 行代码中约有 3 行注释、7 行正文。

注释行包括：
- Python: `#`、三引号 docstring
- TypeScript/React: `//`、`/* */`、`/** */`（JSDoc）

不计入统计的行：纯空行、只有括号的行、import 声明。

### 二、函数注释完整性

**Python 函数要求：**
- docstring 说明功能
- 类型注解（参数和返回值）
- 复杂逻辑的行内注释

**React 组件要求：**
- 组件用途的 JSDoc 注释
- Props 接口的字段说明
- 复杂 Hook 的逻辑注释

### 三、注释内容匹配度

- 注释写的"做什么"和代码实际"做什么"是否一致
- 是否存在"僵尸注释"（代码已改但注释未更新）

## 分级标准

| 级别 | 覆盖率 | 图标 |
|------|--------|------|
| 优秀 | ≥ 30% | 🟢 |
| 一般 | 15-30% | 🟡 |
| 偏低 | 5-15% | 🟠 |
| 严重不足 | < 5% | 🔴 |

## 注意事项

- 只检查不修改，给出报告和建议
- 测试文件（`tests/`、`__tests__/`）覆盖率要求放宽
- 配置文件注释要求放宽
